# work-discipline

长期协作纪律与行为准则。它把「怎么和人协作」固化成一套可执行的硬规则：开工前列清单、扫技能、缺能力先问、交活只认证据、高危先确认，并在写操作和派活时给出完整方法论。

## 能力

- **开工对齐**：每次任务先列目标 + 步骤 + 状态；简单任务直接做，复杂 / 高危任务停下等人确认。
- **扫 skills**：按 description 匹配最合适的 1–3 个加载并说明理由；缺能力时先搜真实候选、问一句，不擅自安装。
- **交活附证据**：前后对比 / 测试 / 回读值 / 链接，不接受「我修好了」。
- **硬边界**：删除、发布、强推、迁移、上传外部、读取密钥 / 用户数据等，先确认再动；禁止自动执行远端写操作。
- **执行层（做对）**：线上变更与批量作业七步法——备份分析 → 列工作条目 → 最小改动 → 小样测试 → 大批量 → 三轮 review → 复盘；每步必须有产出物。
- **委托层（交对）**：派活给 AI / 下属 / 自动化时按四时机动作——开工前复述、执行中消除瓶颈、交活只认证据、出错时改环境。
- **自我维护**：新覆盖旧、写成指令、四问写入门槛、按作用域分层。

## 触发方式

- 每次任务开工前调用该 skill（依赖用户级 `MEMORY.md` 的常驻钩子提醒）。
- 用户说「按记忆执行」「自检」「列出任务」时触发。
- 命中线上写操作 / 批量作业 / 派活 / 改记忆时，往下读对应章节。

## 安装与恢复

1. **目录**：把本仓库的 `skills/work-discipline/SKILL.md` 放到所用工具的 skill 安装目录即启用。
2. **跨设备**：克隆本仓库，把 `skills/work-discipline/SKILL.md` 覆盖到上面的本地路径。
3. **常驻钩子**：用户级 `MEMORY.md` 写一句「每次开工前调用 work-discipline skill」；换机后若丢失需重建，否则触发靠概率。

## 优点

- **把隐性偏好变显式规则**：口头习惯写成可验证的动作，减少「凭印象」导致的漏做。
- **两层咬合**：执行层管「做对」、委托层管「交对」，每条规定都标出与另一层的对应关系，不打架。
- **精简分层**：常驻只放高频硬规则 + 路由索引，低频章节按需加载；主文件从 2821 字符瘦到 1072。
- **经过实测**：用「盲测是否输出动作」+「真实任务后独立路径回读」两招验证过，不是拍脑袋写的。

## 缺点 / 局限

- **启用 ≠ 每次调用**：skill 按需加载靠 AI 自己判断，实测出现过「已经读规则所以跳过调用」——行为合规但触发机制没跑。靠钩子提醒能把概率拉高，但不是硬保证。
- **提示词层，不是硬拦截**：要做到「绝不可能漏」得用 Hook / 脚本硬拦，而桌面端未必支持该机制。
- **规则会稀释**：文件越长越容易被略读；反复写「禁止 X」反而让 X 更活跃，需要定期精简。
- **观点类任务不适用**：写作即思考，这类内容仍需人自己写，skill 只做找 / 整理 / 核实。
