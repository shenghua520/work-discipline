# 委托层｜派活给 AI / 下属 / 自动化

> 触发场景：把任务交出去——派活给 AI、下属、自动化实例。
> 按时机做动作，禁止复述教程。
> **单人 + 单 agent 的桌面场景**：下面涉及「团队 / 幕僚长 / 负责人 / 下属」的条款只在实际有多人或多实例时适用；单人场景只保留「开工前复述 + 交活认证据 + 出错改环境」三条，不满足条件时跳过，不要为了套用而虚构一个团队。

## 开工前

- 复述与工作条目由开场层统一要求（复述 + 理清任务定义 + 用户确认）；派活时额外要求：执行方先读完完整材料再自己复述问题在哪，禁止我先抛我的猜测（「我觉得是 X」会带偏）。→ 开场层 + 执行层第 2 步。
- 一次给简短高质量上下文（谁 / 做什么 / 怎么做），禁止堆海量资料（信息越多它越依赖）。
- 新授权按四步走，禁止跳步：看着做 → 教会并存技能 → 一句指令一次做对 → 才设例行。没看过它做对就放手 = 跳过小样直接批量。→ 执行层第 4 → 5 步。

## 执行中

- 发现我在复制粘贴 / 检查 / 转述上下文 → 立刻停下问「哪一步还需要我、为何来问我」，把这一步教给执行方，让它用真实数据自己找答案（禁止猜、禁止编）。靠喂上下文交出去，不靠盯梢。
- 团队只设一个「幕僚长」入口，我只对它说话；负责人只分派不亲自做；先用透一个再拆，拆分只为专业化 / 好管理。
- 重复机械操作让它写脚本，禁止每次手动点；例行任务 ≤ 每小时一次、事件先过滤；重复活交给新建的专用实例（上下文短、不带历史对话），禁止在聊了很久的主实例上跑例行任务。
- 反馈 / 邀约 / 灵感先入队列攒着，定期一起看，禁止来一单做一单。→ 合并同类项后再动手。

## 交活时

- 只认证据不认话：必须附前后对比 / 测试 / 截图 / 链接；「我修好了」不算。→ 只信回读值（它交活给证据，我核查认证据）。
- 每一步保留叫停权；花钱 / 发布 / 对外发言，先提方案、我点头再执行。→ 高危边界。

## 出错时

- 纠正完必须改环境：按「改结构 > 自动检查 > 写成技能 > 靠人检查」消除致错条件；只纠正不改 = 记账不整改。→ 执行层第 7 步。
- 观点类（推文 / 文章 / 判断）自己写，执行方只做找 / 整理 / 核实——写作即思考。
