# Delegation layer | handing work to AI, teammates, or automations

> Trigger: giving a task away — delegating to AI, teammates, or automated instances.
> Act at each moment; never recite a tutorial.

## Before starting

- Restatement and work items are required by the kickoff layer (restate + clarify the task definition + get user confirmation); for delegation, additionally require that the executor read the complete material first and restate where the problem is themselves — never hand them my guess upfront ("I think it is X" biases them). → kickoff layer + execution layer step 2.
- Give short, high-quality context in one pass (who / what / how); never pile on huge amounts of material (the more information, the more they depend on it).
- New authorization follows four steps, no skipping: watch them do it → teach and persist the skill → one instruction, one correct result → only then make it routine. Letting go without ever seeing them do it right = skipping the small sample and going straight to bulk. → execution layer steps 4 → 5.

## While running

- If you notice yourself copy-pasting, checking, or re-narrating context → stop immediately and ask "which step still needs me, and why are you asking me", then teach that step to the executor so it finds the answer with real data (no guessing, no fabrication). Hand work over by removing your dependency on it, not by supervising it.
- The team has exactly one "chief-of-staff" entry point; I talk only to it. The lead only assigns and does not do the work personally; use one entry point thoroughly before splitting, and split only for specialization / manageability.
- Have repeated mechanical operations become a script; never click through them manually every time. Routine tasks run at most once per hour, with event filtering first; hand repetitive work to a dedicated new instance (short context, no carried conversation history), never run routine work on a main instance that has been chatting for a long time.
- Feedback, invitations, and ideas go into a queue and are reviewed together periodically; never handle one at a time as they arrive. → merge like items before acting.

## When handing off

- Accept evidence, not claims: must include before/after comparison / test / screenshot / link; "I fixed it" does not count. → trust read-back values (they hand off evidence, I verify the evidence).
- Keep the right to stop at every step; for spending money / publishing / speaking externally, propose first and act only after I approve. → hard boundaries.

## When it goes wrong

- After correcting, change the environment: eliminate the conditions that caused the error along the order "change structure > automatic check > write it into a skill > rely on human review". Correcting without changing anything = bookkeeping, not remediation. → execution layer step 7.
- Opinion-based work (posts / articles / judgments) is written by me; the executor only finds, organizes, and verifies — writing is thinking.
