# 执行层｜线上变更与批量作业

> 触发场景：线上写操作、批量作业、提交 / 发布 / 迁移 / 删除类动作。
> 顺序不可跳、不可并；每步必须有产出物，没有产出物 = 没做。

## 七步法

1. **备份分析**：写操作前先只读全量快照（带时间戳，覆盖该模块全部子页签，不只点名的那项）+ 基线表（条数 / ID 区间 / 字段分布）。读配置时先确认该系统的安全读取方式（某些后端对请求体敏感），这类项目细节见 `project-notes.md`。
2. **列工作条目**：plan 表——对象 / 现状 / 目标 / 依据 / 风险 / 验收，一行一个可验证单元；「依据」不许空；想不明白的单列「待确认」，禁止夹在计划里偷跑。
3. **最小改动**：只动点名范围与字段；回写显式重建要改的字段（禁止 `...旧快照` 展开）；先写死「允许改动清单」，验收时清单外零变化。范围外发现的问题——只报告，不动手。
4. **小样测试**：改 1 个（最多一小批）→ 回读 → 三查（目标变了 / 连带没被冲 / 非目标没动）→ 自动回滚。样本挑边界型，禁止挑顺手的；不过就回去改设计，禁止「多试几个看看」。
5. **大批量**：分批 ≤50（保守 20–30）、批间 sleep、逐批日志、失败超阈值立即中止；异步任务必须回读落账，禁止把「受理」当「生效」——具体响应字段因系统而异，见 `project-notes.md`。
6. **多次 review**：至少三轮且角度不同——样本级（抽 3–5 条看合理性）/ 全量级（无过滤全扫，区分哪些字段变了即失败、哪些只报告——分类见 `project-notes.md`）/ 归因级（时间窗 + 主键区间 + 具体 ID 存在性三路交叉）；外加一条独立路径（另起只读脚本、重新登录回读，禁止复用写入脚本的结果）。
7. **总结经验**：工作点台账 + 失败复盘（现象→根因→解法→下次怎么防）+ 回写经验库（按维护文件的门槛）。

## 三条铁律

- 遇阻先取证据，禁止猜（接口名 / 弹窗位置 / 失败原因——历次超时的头号原因）。
- 只信后台接口回读值，不信前台页面（有缓存）；判「不多不少」用具体 ID 存在性，禁止用总数（会漂）。
- 纠错动作本身也是写操作，同样走小样 + 回读，禁止直接批量修。

## 写文件与提交

- **写文件优先走版本控制**：本地改完直接 `add` / `commit` / `push`，不要用网页表单逐字粘贴——粘贴易丢换行、会破坏 YAML frontmatter。确实要在网页端改，改完必须回读校验首行与缩进。
- **提交前确认 git 身份不是占位符**：`git config user.name` / `user.email` 若为 `Your Name` / `your.email@example.com` 这类默认值，先按仓库设好再提交——占位符身份会让提交无法归属。
- **推送后逐字校验**：用哈希比对远端与本地源文件（如 `git show origin/main:<path>` 与本地 `md5sum` 对齐），不接受「推送命令没报错」当作成功证据。
- **密钥不入仓**：写入前确认文件不含令牌、`.env`、真实用户数据；已泄漏的凭据按掩码形式记录，不要在提交信息或日志里回显完整值。
