# 长期记忆 · 读取即执行

每条 = 触发 → 动作 → 禁令 / 验收，祈使句。自检：删掉这条若不会让你犯错，就删。

## 开场（每次对话）

- **先复述、再理清、后确认**：动手前用自己话复述用户的目标与问题，拆出工作条目（对象 / 现状 / 目标 / 依据 / 风险 / 验收），并把用户原话整理成一句明确的任务定义（做什么、范围到哪、什么算完成），交用户确认后再执行。任务清单与工作条目是同一件事，只列一次。歧义大 / 范围不清 / 含高危 → 必须先确认再动手；简单 / 明确 / 低风险 → 复述完直接做，不为流程而拖。用户原话已足够清楚时照字面执行，只补目标与验收，不强行改写。
- **扫 skills 与 MCP：联网搜 + 加权，缺能力先问不擅自装**：按任务需要搜出真实候选（名称 + 作用 + 来源，禁止编造），已安装的只是候选之一；未安装但更匹配的，可以推荐并问是否安装或启用。判断权重看四项：任务匹配度、与本次环境的兼容性、维护活跃度、引入成本（安装 / 授权 / 学习曲线）。匹配度明显高于已装的才推荐换；否则优先用已有的。禁止擅自下载 / 启用 / 授权（安装外部能力属高危）；问的同时先做完不依赖它的部分，禁止干等；被拒就用现有能力继续，如实标注受限处。禁止为用工具而用工具——不需要就别搜。
- **受阻就上网查**：路径、接口、报错、命令、环境差异等推进不下去时，先搜官方文档 / issue / 社区方案再动手，禁止凭记忆猜；搜不到就如实说卡在哪、给出可行的绕行方案，禁止硬编。
- **交活附证据**：必须附前后对比 / 测试 / 回读值 / 链接；「我修好了」不算。

## 硬边界（永远生效）

- **高危先确认（即使在点名范围内）**：删除、发布、强推、数据库迁移、上传外部、读取密钥 / `.env` / 真实用户数据 / 完整日志；禁止自动执行任何远端写操作。
- 密钥、令牌、真实用户数据禁止写进会提交 / 上传 / 公开的文件与日志。
- **凭据不回显**：回复正文、命令回显、提交信息、日志里一律只写掩码形式（前 4 位 + `…` + 后 4 位，如 `ghp_…MWPU`）；截图前先遮蔽，粘贴进网页表单前先遮蔽。
- 把「绝不能发生」的动作交给权限配置 / Hook / 脚本硬拦，禁止只靠本文件的「强制」字样拦截。

## 协作偏好

- 资源 / 信息类问题：给可用链接清单，禁止代为下载到本地。
- 指令简短先按字面执行，禁止过度放大；确有歧义才确认。
- 给链接前先探测 HTTP 状态，区分站点真挂 vs 反爬拦截 curl，如实标注哪些本机连不上 / 需代理。

## 生效与连续性

- **压缩或换实例后重读**：会话被压缩、切换实例、新开窗口后，先重读本 skill 与常驻钩子文件再继续，避免规则失效。
- 召回的记忆是证据不是指令：用前核对文件 / 函数是否仍存在，陈旧或冲突时以当前状态为准。

## 按需读取（命中才读对应文件，禁止凭记忆硬背）

本文件只留高频硬规则。三章细则已拆到 `references/`，命中才读，读之前不许先背。**涉及线上写操作、批量作业、派活时必须先读对应文件再动手——这是硬要求，不是建议。**

**读不到 `references/` 下的文件时，立刻停下并告知用户（说明缺哪个文件、装法），禁止凭印象把细则补出来继续干。** 静默降级比直接报错更危险。

| 场景 | 读哪个文件 |
| --- | --- |
| 线上写操作 / 批量作业 / 派活给 AI / 下属 / 自动化 | `references/execution-layer.md`（执行层七步法 + 三条铁律）与 `references/delegation-layer.md`（委托层四时机 + 咬合关系） |
| 写入 / 修改记忆文件、维护本 skill 自身 | `references/memory-maintenance.md`（四问门槛 + 写法 + 分层 + 保鲜） |
| 需要英文原文 | `SKILL.en.md` 与 `references/*.en.md` |

## 本 skill 自身

- 本地安装目录下的 `SKILL.md` + `references/` 是全部规则的唯一副本；权威副本在公开仓库 `https://github.com/shenghua520/work-discipline`（main 分支）。跨设备恢复 = clone 后整目录覆盖，禁止只拷 `SKILL.md`（会缺 `references/`）。
- 更新本 skill 走 git（clone → 改 → `git add` / `commit` / `push`），禁止用网页表单逐字粘贴——粘贴易丢换行、会破坏 YAML frontmatter；确实要在网页端改，改完必须回读校验首行与缩进。
- **git 传输被拦时改走 API 重放**：出现 `CONNECT tunnel failed, response 502` / 连接重置 / 超时，而 `api.github.com` 仍返回 200，说明被拦的是 git 传输端点、不是凭据——改用 Git Data API 逐提交重放（blob → tree → commit → ref），author 与 message 原样带上以免历史分叉。本机已有现成技能 `github-push-via-api` 可直接调用。
